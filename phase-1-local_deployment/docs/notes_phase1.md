   5. ### Run-Down (Should this be used elsewhere?)
cli.py and api.py are just endpoints to interact with our application. 

`audio_processor.py` prepares input to be compatible with the core process of the app, `model_processor.py`, which loads a model and initializes an Inference session, which allows users to run new input data against the model in `onnxruntime`.
More specifically it loads the .onnx model from disk into memory and prepares the ONNX Runtime for inference. Also, an ONNX model has named inputs and outputs and this code inspects the loaded model to find those names automatically, so they don't have to be hard-coded. 
This is the `__init__` part of the AcousticModelProcessor object, quasi the *"setup phase"*.

Next comes the `generate_vector(self, preprocessed_audio: np.ndarray)` function which defines the *"execution phase"*. As the ONNX Inference session needs the input data in a specific dictionary format, the function starts with the creation of this format by mapping the input name (found in the setup phase) to the NumPy array data of the preprocessed audio input. 

Finally comes the crucial part of running the session, pushing the input data through the model's computations and getting the model output (predictions).
